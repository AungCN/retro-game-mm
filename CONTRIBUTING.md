# Contributing and Working Agreement

## Before contributing

- Read `AGENTS.md`, `GOALS.md`, `PLANS.md`, and the relevant phase/task.
- Check the current Git state and do not overwrite someone else's changes.
- Confirm that the task is in scope and authorized.

## Change process

1. Propose a plan and wait for owner approval.
2. Work on a focused branch or change set.
3. Add tests and update relevant documentation.
4. Run checks and report actual results.
5. Submit evidence for human evaluation.
6. Do not merge or release without explicit owner authorization.

## Definition of done

A task is not done merely because code was generated. It must satisfy its acceptance criteria, pass the applicable automated checks, include necessary documentation, and receive human acceptance where required.
